# Confluence 장애보고서 표준 양식 (5섹션 flat)

사내 장애보고서 표준 양식. 조직의 보고 기준에 맞게 조정하여 사용한다.

## 양식 원칙

- **분량**: 5~7KB 이내 (스크롤 1회 분량, 본부장/임원이 1~2분 내 핵심 파악 가능)
- **구조**: flat — Expand 매크로 회피, 헤딩으로 직접 섹션 분리
- **용어**: 사내 운영팀 공용 어휘 사용 (Classic HW, 이벤트 클리어, 컨콜 등)
- **재발 방지**: 코드 변경 + 배포 일정 결합. 추상 표현 금지
- **영향도**: 정량적 (이벤트 N건, VOC N건, 영향 분 단위)

## 페이지 제목 형식

```
(YYYY.MM.DD) [장애등급] {장애 대상} {장애 내용 요약} [{등급 표기}]
```

예:
- `(YYYY.MM.DD) [장애등급] <서비스명> 장애 내용 요약 [N등급]`
- `(YYYY.MM.DD) <서비스명> 이벤트 연동 불가 장애 [관리장애]`

## 본문 구조

### 1. 장애 기본 정보

bullet 4개 — 핵심만 한 줄씩:

```
- 장애 사항 : {간결한 1줄 설명}
- 상황 반장 : {운영팀명} {담당자명}
- 복구 반장 : {개발팀명} {담당자명}
- 장애 시간 : YYYY.MM.DD HH:MM ~ HH:MM ({총 시간 — "1시간 N분" 형태})
```

### 2. 장애 원인 및 영향도

```
- 장애 원인
  - {원인 1줄}
  - {원인 2줄 — 상위 원인 + 메커니즘}
- 장애 여파
  - {영향 범위 + 시간}
  - {정량적 영향 — VOC 건수, 누락 이벤트 건수 등}
```

### 3. 조치 사항

시간순 짧게 (3~5 bullet):

```
- 장애 기술 문의 (HH:MM / 요청자 → 담당자) 후 원인 분석 (HH:MM ~ HH:MM)
- 원인 파악 후 임시 조치 ({담당자} / HH:MM)
- 임시 조치 이후 정상 동작 확인 (HH:MM / 확인자)
```

### 4. Timetable

**5컬럼 표** (시간 / 상태 / 담당자 / 조치 사항 / 비고):

| 시간 | 상태 | 담당자 | 조치 사항 | 비고 |
|------|------|--------|----------|------|
| YYYY.MM.DD HH:MM | {상태명} | {팀_담당자} | {짧은 조치 설명} | {링크 또는 메모} |

**상태 (Status) 표준 값**:
- `최초 발생` / `최초 인지` / `지속 결함 확인` / `기술 문의` / `컨콜 요청` / `컨콜 개설 및 상황대응` / `장애 원인 분석 및 임시 조치` / `장애 메시지 발송` / `장애 해소 최종 확인` / `장애 복구 메시지 발송` / `장애 원인 세부 분석 완료`

### 5. 재발 방지 대책

```
- {개선 항목 1}
  - {구체 코드 변경 또는 정책 변경 1줄}
  - {구체 코드 변경 또는 정책 변경 1줄}
- Hotfix 배포
  - 통합관제일정 배포 일정 협의 후 M월 D일 ~ D일 중 배포 예정
```

## 작성 시 금지 사항

| 금지 | 사유 |
|------|------|
| Expand 매크로 (`ac:structured-macro ac:name="expand"`) | 임원 가독성 저해 (펼쳐야 읽힘) |
| 추상 표현 ("개선 검토", "추후 진행") | 실행 가능 단위로 명시 |
| 디테일 과다 (코드 라인 번호, 정밀 분석 결과 등) | 핵심만 — 디테일은 부록/링크 |
| 추정 시각 | 정확한 시각 또는 `[미확인]` |

## Storage Format 예시

전체 페이지 storage format 골격:

```html
<h3>1. 장애 기본 정보</h3>
<ul>
<li>장애 사항 : {장애 1줄}</li>
<li>상황 반장 : {운영팀} {이름}</li>
<li>복구 반장 : {개발팀} {이름}</li>
<li>장애 시간 : YYYY.MM.DD HH:MM ~ HH:MM ({시간})</li>
</ul>

<h3>2. 장애 원인 및 영향도</h3>
<ul>
<li>장애 원인
  <ul>
  <li>{원인 1}</li>
  <li>{원인 2}</li>
  </ul>
</li>
<li>장애 여파
  <ul>
  <li>{영향 1}</li>
  <li>{영향 2}</li>
  </ul>
</li>
</ul>

<h3>3. 조치 사항</h3>
<ul>
<li>{조치 1}</li>
<li>{조치 2}</li>
<li>{조치 3}</li>
</ul>

<h3>4. Timetable</h3>
<table>
<tbody>
<tr><th>시간</th><th>상태</th><th>담당자</th><th>조치 사항</th><th>비고</th></tr>
<tr><td>YYYY.MM.DD HH:MM</td><td>{상태}</td><td>{팀_담당자}</td><td>{조치}</td><td>{비고}</td></tr>
</tbody>
</table>

<h3>5. 재발 방지 대책</h3>
<ul>
<li>{개선 항목}
  <ul>
  <li>{구체 변경 1}</li>
  <li>{구체 변경 2}</li>
  </ul>
</li>
<li>Hotfix 배포
  <ul>
  <li>{배포 일정 협의 결과}</li>
  </ul>
</li>
</ul>
```
