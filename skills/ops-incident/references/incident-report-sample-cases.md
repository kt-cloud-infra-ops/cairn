## 2. Confluence 페이지 구조 (표준)

### 2.1 페이지 구성

```
[페이지 제목]
"(YY.MM.DD) {장애 대상} {장애 내용 요약} [{장애 등급}]"
예: "(YYYY.MM.DD) <서비스명> 이벤트 연동 불가 장애 [관리장애]"

[Section 1] 장애 복구 보고 (Expand 매크로)
  - 장애 기본 정보
  - 장애 내용 및 서비스 영향도
  - 서비스 영향 세부 사항
  - 장애 대응 과정 (타임라인)
  - 장애 원인
  - 개선 방안 (간략)
  - 긴급 후속 조치 진행 사항

[Section 2] 고객 장애보고서 (있는 경우만)
  - "사내 장애보고 필요시" Note 매크로

[Section 3] 사내 장애 보고서 (Expand 매크로)
  - ※ 장애 관리 기본 정보 (테이블)
  - 장애 대상
  - 장애 일시
  - 장애 인지 시간 및 방법
  - 서비스 영향
  - 장애 내용
  - 장애 원인 (상세 + 증빙)
  - 장애 조치
  - 장애 후속 긴급 조치
  - 조치 상세 내역 (시간대별 테이블)
  - 재발 방지 및 후속 계획 (개선 항목 테이블)
```

## 4. 작성 시 주의사항 (학습 결과)

### 4.1 표준 양식 준수

- **장애 복구 보고** = 3시간 내 Confluence + Slack
- **사내 장애 보고서** = 5영업일 내 (IPC) Confluence (조직 SLA 기준 적용)
- **고객 장애 보고서** = 고객 영향 없으면 불요 — 확인 후 결정

### 4.2 사례 비교 (이전 사례 vs 현재 사고)

| 항목 | 이전 사례 | 본 사고 |
|------|------------|---------------|
| 등급 | `<이전 사례 등급>` | `[미확인]` |
| 시간 | `<이전 사례 기간>` | `<본 사고 기간>` |
| 원인 | `<이전 사례 원인>` | `<본 사고 원인>` |
| 영향 | `<이전 사례 영향>` | `<본 사고 영향>` |
| 복구 | `<이전 사례 복구>` | `<본 사고 복구>` |
| VOC | `<이전 사례 VOC>` | `[미확인]` |
| 보고서 | 작성됨 | **본 사고 작성 대상** |

### 4.3 보완 포인트

- **상황반장 / 복구반장 명시**: 이전 사례 참고하여 두 명 명시 권장
- **인시던트ID 발급 절차**: 관제팀에서 `INM{YYMMDD}{시퀀스}` 형식으로 발급 (조직 인시던트 ID 형식으로 교체)
- **사내 공지**: 슬랙만으로 진행된 경우 별도 사내공지 누락 여부 확인 필요
