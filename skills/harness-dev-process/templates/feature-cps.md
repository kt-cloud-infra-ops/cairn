# CPS (Context-Problem-Solution)

> 이 문서는 기능 요구사항의 배경과 범위를 고정하는 첫 번째 산출물이다.
> Charter Preflight 4요소(Goal, Context, Constraints, Done When)를 포함해야 한다.

## Charter

```
CHARTER_CHECK:
  Goal: [무엇을 만들/고칠/바꿀 것인가]
  Context: [관련 파일, 문서, 에러, 현재 상태]
  Constraints: [최소 3개 — 아키텍처 규칙, 금지 사항, 기술 제약]
  Done When: [테스트 가능한 완료 기준 — 모호한 표현 금지]
```

Clarification Level: `LOW` / `MEDIUM` / `HIGH`

| # | 항목 | 해당 | 확인 결과 |
|---|------|------|----------|
| 1 | **DB 텍스트 변경 시 전수 탐색** — varchar/text 값 변경이면 `information_schema.columns` 전수 조회로 동일 값 보유 테이블 확인 | | |
| 2 | **UNION ALL 패딩 추적** — `'' as 컬럼명` 또는 `NULL as 컬럼명` 존재 시 SQL→Mapper→Service→Controller→UI 전 레이어 추적 | | |
| 3 | **수정 파일에 DTO/Mapper 포함** — 쿼리 결과 컬럼 변경 시 Mapper 인터페이스, DTO/VO, Builder 수정 파일 명시 | | |
| 4 | **scheduler 발송 경로 교차 검토** — Slack/SMS/Email 발송 로직 변경 시 scheduler 동일 경로 사용 여부 확인 | | |
| 5 | **화면(JSP) 전수 점검** — 조회 결과 렌더링 분기 추가 시 동일 데이터를 표시하는 다른 JSP 확인 | | |

| 7 | **빈 문자열 vs null 처리** — 발송 필터, nvl/COALESCE, isEmpty 조건에서 빈 문자열 통과 여부 확인 | | |
