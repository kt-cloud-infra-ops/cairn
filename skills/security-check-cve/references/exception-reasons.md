# 예외 신청 사유 작성

## 기본 범위

조치 후 **잔존 Critical / High / Medium**. Low는 사용자가 명시적으로 요청한 경우에만 포함한다.

## 필드 순서 (고정)

```text
CVE ID / OS / 패키지 / 심각도 / 사유 분류 / 사유
```

## 사유 분류

| 분류 | 사용 조건 |
|------|-----------|
| `업스트림 패치 미배포` | 배포판·업스트림에 수정 버전이 아직 없음 |
| `호환성 제약` | 수정 버전 적용 시 애플리케이션·확장·클러스터 호환 불가 |
| `런타임 미사용` | 해당 패키지/컴포넌트가 실제 실행 경로에 포함되지 않음 (근거 필요) |
| `상위 릴리스 필요` | 메이저 업그레이드가 필요하고 별도 전환 계획 대상 |
| `오탐` | 스캐너 오탐임을 근거로 제시 가능 |
| `진단 차단` | 도구·권한 제약으로 판정 불가 (조치 예외가 아니라 후속 과제) |

## 사유 문장 규칙

- 1~2문장, 비기술 독자가 이해 가능한 표현
- "무엇이 왜 지금 조치 불가한지" + "대신 무엇으로 위험을 낮추는지" 순서
- 근거 없는 단정 금지 — 확인하지 않은 사실을 사유로 쓰지 않는다
- 자격증명·내부 호스트명·시크릿 언급 금지

좋은 예:

> 해당 라이브러리의 수정 버전이 현재 OS 배포판에 아직 배포되지 않았습니다. 배포 시 즉시 반영 예정이며, 그 전까지는 외부 네트워크 미노출 구성으로 노출면을 제한합니다.

나쁜 예:

> 영향 없음. (근거·대체 통제 없음)

## 중복 처리

동일 소스 패키지에서 파생된 여러 바이너리 패키지는 **하나의 CVE 행으로 묶어** 사유를 작성하되, `CVE 상세` 시트의 원자성(1 CVE = 1행)은 그대로 유지한다.
