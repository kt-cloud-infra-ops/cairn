# 공통 안전 정책 (security-check-cve / security-check-cce)

두 스킬이 공유하는 불변 규칙. 스킬 시작 시 반드시 읽고, 위반 가능성이 보이면 즉시 중단한다.

## 절대 금지

| # | 금지 행위 | 이유 |
|---|-----------|------|
| 1 | 기존 이미지 태그 덮어쓰기 | 재현 불가·롤백 불가 |
| 2 | 사용자 명시 요청 없는 레지스트리 push | 운영 이미지 오염 |
| 3 | 진단 중 Kubernetes 리소스 변경 | 운영 장애 유발 |
| 4 | 검증 증거 없는 성공 보고 | 신뢰 훼손 |
| 5 | 스캔 대상 소스 디렉터리에 생성 파일 쓰기 | 원본 오염 |
| 6 | 자격증명·kubeconfig·시크릿의 리포트/로그 노출 | 정보 유출 |
| 7 | 도구 자동 설치, 요청 스캐너·런타임 무단 교체 | 환경 오염·결과 불일치 |
| 8 | 패키지 저장소 추가, TLS 검증 비활성화 | 공급망 위험 |
| 9 | 원본 이미지에 진단 패키지 설치 | 진단 대상 변조 |

## 결과 분류 (5분류 고정)

| 상태 | 의미 |
|------|------|
| `remediated` | 조치 후 재검증으로 해소 확인 |
| `residual` | 조치 후에도 남은 항목, 위험 감수 |
| `exception` | 호환 조치 불가 → 예외 신청 대상 |
| `false-positive` | 근거를 제시할 수 있는 오탐 |
| `blocked` | 도구·권한·환경 제약으로 판정 불가 |

`blocked`를 `Good`/`해소`로 승격하지 않는다. 권한 거부(permission denied) 결과는 항상 `blocked` 또는 `needs review`다.

## `No fix` 해석

스캐너가 `No fix` / 빈 `fixedVersion`을 반환한 경우:

- "수정 불가 확정"이 아니라 **fix 메타데이터 부재**로 취급한다
- 상위 릴리스 라인, 배포판 보안 공지, 백포트 여부를 한 번 더 확인한 뒤 분류한다
- 확인 없이 곧바로 `exception`으로 처리하지 않는다

## 증거 보존

- 원본 명령과 출력(raw)을 run 디렉터리에 보존한다
- 스캐너 이름·버전·취약점 DB 버전·갱신시각을 기록한다
- Confluence·Harbor 등 외부 기준 데이터는 페이지/아티팩트 식별자와 수집 시각을 함께 남긴다

## 에뮬레이션 라벨링

호스트와 대상 이미지의 아키텍처가 다른 상태에서 CPU 에뮬레이션으로 수행한 검증은 `emulated / not production-verified`로 라벨링하고, 네이티브 검증 건수에 포함하지 않는다.

## 자격증명 취급

- 기존 credential helper 또는 사용자가 **이름만** 알려준 robot-account 환경변수를 사용한다
- 평문 자격증명을 요청·저장·출력하지 않는다
- 사용자 지정 CA 경로는 명시적으로만 사용한다. TLS 검증을 기본 비활성화하지 않는다
- URL에 자격증명이 포함된 입력은 거부하고, 쿼리스트링을 에코하지 않는다
