## 유지가능성 — 결정층 적립 의무 (CRITICAL)

이 서비스는 owner 부재(휴직·이직·담당 이동)에도 **팀 + AI로 같은 수준의 유지보수**가 가능해야 한다.
그러려면 "왜"가 owner 머릿속이 아니라 **코드 밖 문서**에 남아야 한다.

### 코드 변경 시
- [ ] 도메인 에이전트(`agents/domain/{module}.md`) **먼저 읽고** 작업
- [ ] 비가역·위험 설계 결정 → `docs/decisions/`에 ADR 작성 (**되돌리면 안 되는 이유** 필수)
- [ ] 작업 후 새로 확정된 스펙·판단을 도메인 에이전트의 **결정 이력 / 판단 시나리오 / 요구사항 이력**에 적립
- [ ] "모르고 바꾸면 사고나는" 지점은 결정 이력의 **바꾸면 안 되는 경계**에 명시

### 적립 원칙
- 한 번에 몰아 쓰지 않는다. **평소 작업의 부산물로** 한 줄씩 누적한다.
- 절차(How)는 SOP, 규칙(What)은 도메인 준수 규칙, **결정(Why)은 도메인 에이전트 + ADR**.

### 유지가능성 검증 (주기적)
> owner 개입 없이, 팀원 + AI가 위 문서들만으로 운영 태스크 1건을 완수할 수 있는가?

막히는 지점 = 다음에 채울 갭. (도메인 에이전트 충실도 · ADR 커버리지 · 리허설 통과로 측정)
