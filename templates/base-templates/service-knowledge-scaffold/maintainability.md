# 유지가능성 — drift 방지 / 측정 기준

팀원↑ + AI 읽음 환경에서 결정층 문서가 **썩지 않게** 하는 장치. 핵심 원칙:

> AI는 틀린 문서도 그대로 신뢰한다 → **신선도 유지가 작성보다 중요**. 사람 수동 관리 부담은 0에 수렴시키고, 적립·검증·최신화를 자동화한다.

## 3가지 건강 신호

| 신호 | 측정 | 경고 기준 |
|------|------|----------|
| **stale (신선도)** | `last_verified` 나이 + triggers 코드 최종 변경일 | 코드가 `last_verified` 이후 변경됐는데 미검증, 또는 `last_verified` 90일 초과 |
| **충실도** | 결정 이력 / 판단 시나리오 섹션 실내용 유무 | 예시(`_예:_`)만 있고 실제 항목 0건 |
| **커버리지** | Controller·핵심 모듈 대비 도메인 에이전트 수 | 코드 모듈은 있는데 대응 도메인 에이전트 없음 |

## drift 방지 메커니즘 (자동, 사람 부담 0)

1. **적립 — 작업 부산물**: 코드 변경 시 도메인 에이전트에 결정 한 줄 + `last_verified` 갱신 (AGENTS 의무 + Phase 강제)
2. **감지 — 측정 스킬**: `/analytics-maintainability`가 전 서비스 스캔 → stale/충실도/커버리지 리포트
3. **환기 — hook(선택)**: triggers 코드 편집 시 대응 도메인 에이전트가 stale이면 PostToolUse 경고
4. **모순 점검 — 정기**: `meta-harnessing`이 "한 사실은 한 곳" 위반(중복·모순) 검출

## 분산 소유 (팀원↑ 대응)

- 각 도메인 에이전트/ADR에 `maintainer` 명시 → 중앙 1명이 전체 관리하지 않음
- 측정 스킬 리포트는 maintainer별로 그룹핑 → "내 그릇만" 챙기면 됨

## 적용 주기

- **상시**: 코드 변경 시 적립 + `last_verified` 갱신 (작업 흐름 내장)
- **주기**: 주 1회 `/analytics-maintainability` (work-start 또는 weekly에 편입 가능)
- **리허설**: 분기 1회 "owner 없이 AI+팀원이 운영 1건 완수" 검증

## 측정 도구

`agents/skills/analytics-maintainability/` — 전 서비스 결정층 스캔 + 건강 리포트.
